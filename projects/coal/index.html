Are these two objects touching? If not, how far apart are they?

Robots ask this thousands of times a second: before an arm moves, when a foot lands, at every step of a simulation. COAL answers quickly and precisely for almost any pair of 3D shapes. Our adaptation also reports how that answer changes when an object moves, which motion planners and learning systems need.

Credit where it's due: Coal is not our library. It is developed by the Coal team (mainly Inria and LAAS-CNRS) and grew out of FCL, the Flexible Collision Library started at Willow Team. We adapted it for our own research: it keeps Coal's names and interfaces, and adds contact derivatives, a TruncatedCone shape, and a browser playground.

Why it matters

Every robot keeps asking the same question.

A robot only knows the shapes of its own body and of the world around it. Software has to work out when those shapes meet. Every query comes down to two answers: are they touching, and how close or how deep?

PlanningMoving safely

Before it moves, an arm checks every candidate path against shelves, tables, and people. A planner can test millions of poses.

SimulationSimulating contact

A physics engine needs to know where a foot touches the ground and how deeply, so it can compute the contact force.

OptimizationLearning which way to move

Optimizers also need to know which way to move to make or avoid contact. That is the derivative of the answer, covered further down.

How it works

Turn two shapes into one, then look for the origin.

Checking every surface point of one shape against every point of the other would be far too slow. COAL narrows the work down in stages.

Step 01Quick box check

Each object gets a simple bounding box. If two boxes don't overlap, the objects can't touch, so most pairs are ruled out almost instantly. Tick show bounding boxes in the demo to watch this.

Step 02Combine the two shapes

For pairs that pass, subtract every point of B from every point of A. The objects touch exactly when that combined shape contains the origin, and the gap equals the origin's distance to it.

Step 03Search efficiently

COAL never builds the combined shape in full. GJK (for distance) and EPA (for penetration depth) probe just a few of its points to find the closest one to the origin. Coal's accelerated GJK is 5 to 15 times faster than widely used alternatives.1

Watch the right-hand panel: when the shapes overlap, the origin ends up inside A − B.

What our adaptation adds

How does the answer change when something moves?

A planner steering an arm away from an obstacle needs more than the distance. It needs to know how the distance will change for each small move it could make, which is the derivative. Computing it reliably is our main addition. Predict the new distance from the derivative, then compare with the true answer.

Our adaptation

The original Coal, plus three additions.

Upstream Coal grew out of the Flexible Collision Library (FCL) and was renamed from HPP-FCL in 2024. It powers Pinocchio, Crocoddyl, the Humanoid Path Planner, and the Simple simulator. It supports boxes, spheres, capsules, cylinders, cones, ellipsoids, planes, convex meshes, height fields, and octrees. Our adaptation keeps the coal:: and import coal interfaces and adds:

NewContact derivatives

For any contact: how the witness points, normal, and signed distance change under a small rigid motion. Choose exact piecewise geometry, or randomized smoothing for a softer estimate.

NewTruncated cone

A cone with its tip cut off and independent top and bottom radii. Supported by collision, distance, contact patches, serialization, and both Python bindings.

NewBrowser playground

The interactive 3D page above. It runs COAL's real solvers via WebAssembly, so anyone can explore contacts and check derivatives.

1. Benchmarks are from the upstream Coal project and compare Coal with Bullet, FCL, and libccd. See the upstream README.

Quickstart

Build it, then query a contact and its derivative.

Build from source with Pixi. The test task installs dependencies, builds, and runs the test suite.

shell
git clone --recurse-submodules --branch devel https://github.com/GVSRobotics/coal.git
cd coal
pixi run -e all test
pixi run -e all cmake --install build
pixi run -e all python -c "import coal; print(coal.TruncatedCone)"
main.cpp
#include <coal/contact_derivatives.h>

coal::Ellipsoid a(1.0, 0.7, 0.5), b(0.8, 0.6, 0.4);
coal::Transform3s T_AB(coal::Matrix3s::Identity(), coal::Vec3s(2.2, 0.1, 0.2));

auto result = coal::derivatives::query(a, b, T_AB);
if (result.available && result.exact) {
  Eigen::Matrix<coal::Scalar, 6, 1> xi;      // small motion of B: [rotation; translation]
  xi << 0, 0, 0.001, 0.002, 0, 0;
  coal::Scalar predicted_d = result.distance + (result.distance_jacobian * xi)(0);
}
