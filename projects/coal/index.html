COAL

Are these two objects touching? If not, how far apart are they?

Robots ask this thousands of times a second: before an arm moves, when a foot lands, at every step of a simulation. COAL answers quickly and precisely for almost any pair of 3D shapes. Our fork also reports how that answer changes when an object moves, which motion planners and learning systems need.

A fork of Coal, the open-source collision library behind Pinocchio and other robotics frameworks. This fork adds contact derivatives, a TruncatedCone shape, and a browser playground.

01

Why robots need collision detection

A robot only knows the shapes of its own body and of the world around it. Software has to work out when those shapes meet. Every query comes down to two answers: are they touching, and how close or how deep?

🦾

Planning safe motion

Before moving, an arm checks every candidate path against shelves, tables, and people. A typical planner tests millions of poses.

🦶

Simulating contact

A physics engine must know where a foot touches the ground and how deeply. It uses that to compute the contact force.

🧠

Learning and optimizing

Optimizers also need to know which way to move to make contact or avoid it. That is the derivative of the answer (section 4).

03

How COAL answers so fast

Checking every surface point of one shape against every point of the other would be far too slow. COAL narrows the work down in stages.

Step 1 · Quick box check

Each object gets a simple bounding box around it. If two boxes don't overlap, the objects can't touch, so most pairs are ruled out almost instantly. Turn on Show bounding boxes in the demo to watch this.

Step 2 · Combine the two shapes

For pairs that pass, COAL subtracts every point of B from every point of A. The result is a single combined shape, shown on the right. The objects touch exactly when that shape contains the origin (the ⊕ mark), and the gap between them equals the distance from the origin to that shape.

Step 3 · Search efficiently

COAL never builds the combined shape in full. Two classic algorithms, GJK for distance and EPA for penetration depth, probe only a handful of its points to find the closest one to the origin. Coal's accelerated GJK is 5 to 15 times faster than widely used alternatives.1

Watch the right-hand panel as you drag. When the orange shape enters the blue one, the origin ends up inside the combined shape. The dashed line from the origin to the nearest edge has the same length as the gap or overlap in the left-hand panel.

04

What if the shape moves a little?

A planner trying to move an arm away from an obstacle needs more than the distance. It needs to know how the distance will change for each small move it could make. Mathematicians call this the derivative. Computing it reliably is the main addition in this fork.

06

What this fork adds

Upstream Coal is a mature library used across robotics. We keep its names and interfaces (coal::, import coal) and add three things.

Contact derivatives

For any contact, how the witness points, normal, and signed distance change under a small rigid motion. Two methods are available: exact piecewise geometry, or randomized smoothing for a softer estimate.

Truncated cone

A new primitive shape: a cone with its tip cut off, with different top and bottom radii. Supported by collision, distance, contact patches, serialization, and both Python bindings.

Browser playground

The interactive 3D page above. It runs COAL's real solvers via WebAssembly, so you can explore contacts and check derivatives without installing anything.

Built on a widely used library

Coal grew out of the Flexible Collision Library (FCL) and was renamed from HPP-FCL in 2024. Upstream Coal powers Pinocchio, Crocoddyl, the Humanoid Path Planner, and the Simple simulator. It supports boxes, spheres, capsules, cylinders, cones, ellipsoids, planes, convex meshes, height fields, and octrees.

1. Benchmarks are from the upstream Coal project and compare Coal with Bullet, FCL, and libccd; see the upstream README. If you use Coal in research, please cite it.

07

For developers

Build this fork from source with Pixi. The test task installs dependencies, builds, and runs the test suite.

git clone --recurse-submodules --branch devel https://github.com/GVSRobotics/coal.git
cd coal
pixi run -e all test
pixi run -e all cmake --install build
pixi run -e all python -c "import coal; print(coal.TruncatedCone)"

Query a contact and its derivative

#include <coal/contact_derivatives.h>

coal::Ellipsoid a(1.0, 0.7, 0.5), b(0.8, 0.6, 0.4);
coal::Transform3s T_AB(coal::Matrix3s::Identity(), coal::Vec3s(2.2, 0.1, 0.2));

auto result = coal::derivatives::query(a, b, T_AB);
if (result.available && result.exact) {
  Eigen::Matrix<coal::Scalar, 6, 1> xi;            // small motion of B: [rotation; translation]
  xi << 0, 0, 0.001, 0.002, 0, 0;
  coal::Scalar predicted_d = result.distance + (result.distance_jacobian * xi)(0);
}
